# 升级与回退

本说明覆盖 0.10 系列的“登记来源”功能。0.19.1 已本地安装，尚未发布到 npm 或插件市场；安装与页面验收范围见验收记录，不等于后端备份/恢复验证。

## 先确认备份覆盖范围

钩子规则属于 Host 的 `storageDomain`，域名为 `abworks_generic_hooks`，不是插件安装目录，也不保证存放在名为 `pluginData` 的目录中。后端由 Host 路由，不能猜测固定路径。

- 不要把插件安装包、源码副本、Codex 原始文件或仅含 `pluginData` 的配置导出当作规则状态备份。它们未必包含规则、信任摘要、登记及归属关系。
- 本次现场仅导出 `pluginData` 时，Host 明确报告该目录为空或不存在。因此该归档**没有证明覆盖钩子状态，不能用于宣称可恢复**。
- 若使用 Host 或存储后端的备份机制，须确认实际包含上述域，并按其说明制作一致性备份、验证恢复。暂停钩子不等于关闭整个存储后端；不要直接复制正在写入的数据库并假定备份有效。
- 状态可能含命令参数、绝对路径和信任摘要，应当按敏感配置保存；不要贴到公开 issue。没有可验证备份时，不执行可能覆盖状态的手工恢复。

本插件尚无通用的备份文件导入/恢复入口。受控测试中的 JSON 快照往返只验证 manager 状态能序列化，不证明 Host 配置导出已覆盖它，也不是让用户修改运行中的存储文件。

## 使用新版本

升级前保持全局执行暂停，记录原版本。安装后先确认设置入口、现有规则和来源状态，再决定是否逐条启用；不要因为安装成功就启用全部规则。

普通快照导入不会自动变为持续关联。登记来源时明确选择固定文件、解释器和独立目标范围；新规则关闭且未信任。启动及周期检查会使变化的所属规则停用；轮询不是实时防线，文件恢复原样也不能自动恢复资格。

## 从登记来源版本回退到 0.9.0

旧版使用严格的状态 schema，不能直接读取带 `sourceRegistrations` 的状态；存储版本号未变不代表向后兼容。

1. 在仍可使用的新版本中暂停全局执行，保留经验证的备份。
2. 在“用户配置”的已登记来源中逐份解除关联。不要删原始文件来代替解除；删除会留下登记和待审状态。
3. 解除保留规则快照，对仍匹配归属的规则关闭并清除信任；不会覆盖本地编辑或恢复被删项。它不保证已启动的进程或其后代已经退出。
4. 所有登记解除后确认列表为空。最后一份解除会省略持久状态中的 `sourceRegistrations` 字段；部分解除仍不能回退。
5. 再安装原版，在执行暂停状态检查规则。解除关联不是撤销脚本已经造成的文件、网络或审批副作用，也不会改写 Codex 来源文件。

该路径只验证登记字段与旧状态外壳的兼容，不能保证更早版本理解所有新规则字段。回退安装失败时保留当前状态，恢复可读的新版本后检查，不手工删域、不反复覆盖存储、不把不明备份直接回填。

## 已验证与未验证

- 真实临时 JSON 文件、两份登记、暂停状态 JSON 往返和逐份解除后旧严格外壳校验均有测试；源文件字节不变，无用户命令执行。
- 保存失败、旧 revision、所有权冲突、最后一份解除和来源变化后的恢复保护另有回归。
- 尚未验证真实 Host 后端备份/恢复或回退安装；也未提供备份已覆盖用户数据的保证。
